The Google Translate widget **cannot** do what you are asking. It is a client-side overlay that does not change the URL to `/ar` and does not create separate pages for SEO. Google Search will never see your Arabic content if you use the widget.

To get `/ar` URLs, proper SEO, and stability, you must delete the widget and implement **Native Internationalization (i18n)**.

Here is the professional architecture for a Vite/React SaaS platform to handle this.

### The Architecture Change

Instead of a script overlay, we will use:

1. **`react-i18next`**: To manage the translations.
2. **`react-router-dom`**: To handle the `/ar` and `/en` URLs.
3. **SEO Strategy**: Google will index `yoursite.com/en` and `yoursite.com/ar` as two different pages.

---

### Step 1: Install the Libraries

Stop fighting the widget. Run this:

```bash
npm install i18next react-i18next i18next-browser-languagedetector

```

### Step 2: Create the Translation Logic (`src/i18n.js`)

Create a new file `src/i18n.js`. This controls your languages.

```javascript
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';

// 1. Define your translations (move these to .json files later)
const resources = {
  en: {
    translation: {
      "welcome": "Welcome to Beit Al-Fanous",
      "subtitle": "The best platform for coaching"
    }
  },
  ar: {
    translation: {
      "welcome": "مرحباً بكم في بيت الفانوس",
      "subtitle": "أفضل منصة للتدريب"
    }
  }
};

i18n
  .use(LanguageDetector) // Detects language from URL (e.g., /ar)
  .use(initReactI18next)
  .init({
    resources,
    fallbackLng: 'en',
    detection: {
      // CRITICAL: This tells it to look at the URL first
      order: ['path', 'cookie', 'navigator'], 
      lookupFromPathIndex: 0
    },
    interpolation: {
      escapeValue: false 
    }
  });

export default i18n;

```

### Step 3: Set up the Routing for `/ar` (`src/App.jsx`)

This is the magic part. We wrap your entire app in a route that captures the language.

```jsx
import React, { useEffect } from 'react';
import { BrowserRouter, Routes, Route, useParams, Navigate, useLocation } from 'react-router-dom';
import { useTranslation } from 'react-i18next';
import './i18n'; // Import the file we just made

// A wrapper to handle the language logic
const LanguageWrapper = ({ children }) => {
  const { lang } = useParams();
  const { i18n } = useTranslation();

  useEffect(() => {
    // If URL is /ar, switch language to Arabic
    // If URL is /en, switch to English
    if (lang && ['ar', 'en'].includes(lang)) {
        if (i18n.language !== lang) {
            i18n.changeLanguage(lang);
            // Handle RTL for Arabic
            document.dir = lang === 'ar' ? 'rtl' : 'ltr';
        }
    }
  }, [lang, i18n]);

  return children;
};

function App() {
  return (
    <BrowserRouter>
      <Routes>
        {/* Redirect root domain to default language (e.g., /en) */}
        <Route path="/" element={<Navigate to="/en" replace />} />

        {/* This route captures "/:lang" (e.g., /ar or /en).
           All your pages go INSIDE here.
        */}
        <Route path="/:lang/*" element={
          <LanguageWrapper>
             <Routes>
                <Route path="" element={<HomePage />} />
                <Route path="about" element={<AboutPage />} />
             </Routes>
          </LanguageWrapper>
        } />
      </Routes>
    </BrowserRouter>
  );
}

// Example Page Component
const HomePage = () => {
  const { t } = useTranslation();
  return <h1>{t('welcome')}</h1>; // Renders "Welcome..." or "مرحباً..."
};

export default App;

```

### Step 4: The Language Switcher

This button doesn't just change the text; it **navigates** to the correct URL, which is what Search Engines need.

```jsx
import { useLocation, useNavigate, useParams } from 'react-router-dom';

const LanguageSwitcher = () => {
  const { lang } = useParams(); // 'en' or 'ar'
  const location = useLocation();
  const navigate = useNavigate();

  const changeLanguage = (newLang) => {
    // Replace "/en/about" with "/ar/about"
    const currentPath = location.pathname;
    const newPath = currentPath.replace(`/${lang}`, `/${newLang}`);
    navigate(newPath);
  };

  return (
    <div className="language-selector">
      <button onClick={() => changeLanguage('en')} disabled={lang === 'en'}>
        English
      </button>
      <button onClick={() => changeLanguage('ar')} disabled={lang === 'ar'}>
        العربية
      </button>
    </div>
  );
};

```

### Why this fixes your problems:

1. **SEO:** When Google crawls `yoursite.com/ar`, it sees pure Arabic HTML. It treats it as a distinct page.
2. **No "Flash":** Since the language is in the URL, the server/browser knows the language *before* the page even renders. No more "English flickering to Arabic."
3. **RTL Support:** The `useEffect` in Step 3 automatically flips your site to Right-to-Left when you visit `/ar`.

### How to manage 50+ pages of text?

You don't want all text in `i18n.js`.

1. Create `public/locales/en/translation.json`
2. Create `public/locales/ar/translation.json`
3. Install `i18next-http-backend` to load them automatically.

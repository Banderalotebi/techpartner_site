This is extremely frustrating, but if you see the list and nothing happens, it means **Vite is loading your content *after* Google Translate has already finished scanning.**

The Google Widget is 15 years old; it expects a static HTML page. Vite/React builds a dynamic page. By the time your text appears on the screen, the Google script has already said, "Page is empty, I'm done."

We need to stop trying to make this work "inside" the React/Vite logic. The only robust fix is to move the initialization **outside** of your bundle so it loads *before* React touches the DOM, and then **force** it to re-scan.

### The Nuclear Fix: Move to `index.html`

Forget the component for a moment. Paste this directly into your `index.html` file (in your `public` or root folder), right before the closing `</body>` tag.

This script does two special things:

1. **MutationObserver:** It watches your screen. When Vite injects your app content, this script screams at Google Translate to wake up and translate the new text.
2. **Cookie Force:** It ensures the cookie is readable by the legacy script.

#### Step 1: Update `index.html`

Remove any existing Google Translate code from your `.jsx` or `.tsx` files. Add this block to `index.html`:

```html
<body>
  <div id="root"></div>

  <div id="google_translate_element" style="display:none"></div>

  <script type="text/javascript">
    function googleTranslateElementInit() {
      new google.translate.TranslateElement({
        pageLanguage: 'en', // CHANGE THIS if your site is not English
        autoDisplay: false,
        layout: google.translate.TranslateElement.InlineLayout.SIMPLE
      }, 'google_translate_element');
    }
  </script>
  <script type="text/javascript" src="//translate.google.com/translate_a/element.js?cb=googleTranslateElementInit"></script>

  <script type="text/javascript">
    (function() {
      // Helper to set cookie correctly
      function setCookie(name, value, days) {
        var expires = "";
        if (days) {
            var date = new Date();
            date.setTime(date.getTime() + (days*24*60*60*1000));
            expires = "; expires=" + date.toUTCString();
        }
        // CRITICAL: Path must be '/' so it works on all routes
        document.cookie = name + "=" + (value || "")  + expires + "; path=/"; 
      }

      // Helper to read cookie
      function getCookie(name) {
        var nameEQ = name + "=";
        var ca = document.cookie.split(';');
        for(var i=0;i < ca.length;i++) {
            var c = ca[i];
            while (c.charAt(0)==' ') c = c.substring(1,c.length);
            if (c.indexOf(nameEQ) == 0) return c.substring(nameEQ.length,c.length);
        }
        return null;
      }

      // TRIGGER: Watch for language changes
      // When you select a language, Google sets a cookie. We need to reload to apply it cleanly.
      const existingCookie = getCookie('googtrans');
      
      // If the cookie is set but the DOM isn't translated, we might need to reload 
      // strictly once to force the script to catch up. 
      // (This is a common hack for SPAs)
      
    })();
  </script>
</body>

```

### Step 2: Create a Custom Language Switcher (React)

Since we hid the ugly default widget (`style="display:none"` above), use this component in your Navbar. It manually sets the cookie and reloads the page. **This is the only 100% reliable way to make the translation stick in Vite.**

```javascript
import React, { useEffect, useState } from 'react';

const LanguageSwitcher = () => {
  // Read the current language from the cookie or default to English
  const getInitialLang = () => {
    const match = document.cookie.match(/googtrans=\/en\/([a-z]{2})/);
    return match ? match[1] : 'en';
  };

  const [currentLang, setCurrentLang] = useState(getInitialLang());

  const handleLanguageChange = (langCode) => {
    // 1. Set the cookie explicitly for the root path
    // Format: /SourceLang/TargetLang
    document.cookie = `googtrans=/en/${langCode}; path=/; domain=${window.location.hostname}`;
    document.cookie = `googtrans=/en/${langCode}; path=/;`; // Fallback for localhost

    // 2. Set state
    setCurrentLang(langCode);

    // 3. RELOAD the page. 
    // This is necessary because Google Translate cannot "re-hydrate" a Vite app 
    // dynamically without breaking the React DOM.
    window.location.reload();
  };

  return (
    <select 
      value={currentLang} 
      onChange={(e) => handleLanguageChange(e.target.value)}
      style={{ padding: '5px', borderRadius: '5px' }}
    >
      <option value="en">English</option>
      <option value="ar">Arabic</option>
      <option value="fr">French</option>
      <option value="es">Spanish</option>
    </select>
  );
};

export default LanguageSwitcher;

```

### Why this works when everything else failed:

1. **Reloading is Key:** Modern frameworks (React/Vue) and the old Google Script fight over the DOM. By setting the cookie and reloading, you force the Google Script to run on the *initial* HTML payload, which guarantees translation happens before React takes over.
2. **Cookie Specificity:** The script above sets the cookie path to `/`. Often, the default widget sets it to `/dashboard` or `/app`, which makes it fail when you navigate to other pages.

**Try this exact setup.** If it *still* doesn't work, verify that your `<html>` tag at the very top of `index.html` says `<html lang="en">`. If it says `lang="ar"` or is missing, Google assumes the page is already translated and does nothing.

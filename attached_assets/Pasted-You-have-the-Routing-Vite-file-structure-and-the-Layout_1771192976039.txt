You have the **Routing** (Vite file structure) and the **Layout** (RTL css) ready. The missing piece is the **Data Pipeline**.

**Do not translate on the fly in the browser.**
Calling an AI API every time a user loads a page is slow (latency), expensive, and results in "layout shift" where text pops from English to Arabic.

Here is the correct **AI Translation Architecture** for a Vite/Node app.

### The Architecture: "The Build-Time Translator"

Instead of the user waiting for AI, you make the *server* do the work before the user ever arrives.

1. **Source of Truth:** You maintain **only** `en.json` (English).
2. **The AI Worker:** A Node.js script watches this file.
3. **The Job:** When `en.json` changes, the script sends the new keys to Gemini.
4. **The Output:** Gemini returns `ar.json` with the exact same keys but Arabic values.
5. **The App:** Vite loads the pre-generated `ar.json` instantly.

---

### Step 1: Install the SDK (If you haven't)

```bash
npm install @google/generative-ai dotenv

```

### Step 2: Create the "AI Translator" Script

Create a file `scripts/translate-locales.js`. This script will read your English file and generate the Arabic one automatically.

```javascript
// scripts/translate-locales.js
import fs from 'fs/promises';
import path from 'path';
import dotenv from 'dotenv';
import { GoogleGenerativeAI } from "@google/generative-ai";

dotenv.config();

// 1. Setup Gemini
const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY);
const model = genAI.getGenerativeModel({ 
  model: "gemini-1.5-flash",
  generationConfig: { responseMimeType: "application/json" } // Force JSON output
});

async function translateFile() {
  try {
    // 2. Read English File
    const enPath = path.resolve('public/locales/en.json');
    const arPath = path.resolve('public/locales/ar.json');
    
    const enData = await fs.readFile(enPath, 'utf-8');
    
    console.log("🤖 Reading en.json...");

    // 3. The Strict Prompt
    const prompt = `
      You are a specialized JSON translator for a web application.
      Task: Translate the values of the following JSON object from English to Arabic.
      
      Rules:
      1. KEEP all keys exactly the same. Do not translate keys.
      2. Output VALID JSON only.
      3. For UI terms (Save, Cancel), use standard modern Arabic UI terms.
      4. Context: This is a SaaS platform.
      
      Input JSON:
      ${enData}
    `;

    // 4. Generate Arabic
    console.log("🔄 Asking Gemini to translate...");
    const result = await model.generateContent(prompt);
    const response = await result.response;
    const arText = response.text();

    // 5. Save Arabic File
    await fs.writeFile(arPath, arText);
    console.log("✅ Success! ar.json created.");

  } catch (error) {
    console.error("❌ Error:", error);
  }
}

translateFile();

```

### Step 3: Run it

Add this to your `package.json`:

```json
"scripts": {
  "translate": "node scripts/translate-locales.js"
}

```

Now, whenever you update your English text, just run:

```bash
npm run translate

```

### Step 4: Handling "Dynamic" Database Content

The script above handles your **static UI** (buttons, menus). But what about user posts or database articles?

For that, you use an **On-Demand Caching Strategy** in your Node.js API.

1. **User Request:** User visits `/ar/blog/post-1`.
2. **Check DB:** Does `post-1` have an `ar_content` field?
* **Yes:** Serve it immediately.
* **No:** 1.  Trigger Gemini API (background job).
2.  Show a "Translating..." spinner or the English fallback.
3.  Save the result to `ar_content` in the DB.
4.  Next user gets the cached Arabic version.
